# Política de Segurança

## Reportando vulnerabilidades

A segurança do Portfolio é importante. Caso você identifique uma possível vulnerabilidade, solicitamos que não publique detalhes técnicos em Issues, Pull Requests ou discussões públicas antes que o problema seja analisado.

### Como enviar um relatório privado

O repositório disponibiliza o recurso **Private Vulnerability Reporting** do GitHub.

Para enviar um relatório:

1. Acesse https://github.com/tirolasca/Portfolio.
2. Abra a aba **Security**.
3. Acesse **Advisories**.
4. Selecione **Report a vulnerability**.
5. Preencha o formulário com os detalhes do problema.

Sempre que possível, inclua:

- Descrição da vulnerabilidade.
- Etapas para reproduzir o problema.
- Componentes ou arquivos afetados.
- Impacto potencial.
- Prova de conceito, quando disponível.

O relatório será encaminhado privadamente aos responsáveis pelo repositório.

### Tratamento dos relatórios

Os relatórios recebidos serão analisados para verificar sua validade, impacto e possibilidade de exploração.

Caso sejam necessárias informações adicionais, o contato poderá ocorrer pelo próprio canal privado do GitHub.

Quando uma vulnerabilidade for confirmada, serão avaliadas as medidas corretivas adequadas e a comunicação necessária.

### Divulgação responsável

Solicitamos que pesquisadores aguardem a análise e a eventual correção antes de divulgar publicamente detalhes técnicos que possam permitir a exploração da vulnerabilidade.

### Escopo

Esta política se aplica ao código-fonte e aos componentes mantidos diretamente neste repositório.

### Documentação técnica

Para conhecer os mecanismos de segurança implementados no projeto, incluindo cabeçalhos HTTP, Content Security Policy, GitHub Actions e ferramentas de análise, consulte [`docs/SECURITY.md`](docs/SECURITY.md).
